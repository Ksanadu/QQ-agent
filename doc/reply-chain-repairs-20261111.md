# 回复链路修复与分轮验收（2026-11-11）

基线：cbe3930。范围为此前审查的六项缺陷，以及合并回归时发现的旧积压状态遗漏。

## 第一轮：补充与撤回

- 连续补充淘汰的旧稿不再计作“无进展”，实际成功的工具轮数仍受同一预算约束。
- 交付机会耗尽后，仅移交尚未处理的补充；接收端尚在解析的引用/语音预留也会移交。最多自动接续一次，记录 continuedFrom，不重跑原批次的副作用。
- 撤回使在途旧回复失效。未开始外部写操作时，用剩余有效请求重新组装；已开始的操作保留真实结果，不自动重跑。
- 引用预览、历史查询、图片查询和任务摘要均检查撤回；撤回先于入库也会留下持久记录。管理员原始存档不删除。

验收通过：连续四次补充、额度耗尽后的非 @ 接续、失败时引用尚未入库、唯一请求撤回、引用目标撤回、真实模拟 OneBot 撤回事件及先撤回后入库。

## 第二轮：发送回执与语音完结

- send_message 必须有有效 QQ 消息 ID；缺失/矛盾的成功回执先核验真实送达，未核实则停止本轮发送，阻止自动及手动重跑。
- 部分分段送达不会解锁 finish。retryFailed:true 只补发明确失败的部分，另一条无关文字不能清掉待办。
- 语音成功后允许当前聊天的一句文字确认；演练、冷却和失败也可以文字反馈。跨会话语音不会擅自退化成向目标发文字。
- 文字成功仍只是正常完结的必要条件，不会自动截断表情或其他后续工具。

验收通过：部分成功与定向补发、真实自发回显恢复消息 ID、零 ID、矛盾回执、不重复提交、语音成功后的文字确认、演练和未开启跨会话时的当前聊天反馈。语音验收使用实际技能钩子，替换合成步骤，未运行真实神经合成。

## 第三轮：中止与启动竞争

- 原生搜索、网页和图片读取、B 站及 Bangumi 查询传递会话取消信号。旧只读适配器的迟到结果不会继续模型循环。
- 模型、工具、发送前等待、重试和备用模型共用默认 180 秒总时限，配置为 sessionTimeoutMs。
- 已提交 QQ 的消息仍完成回执核验；中止不伪造撤销，也不再执行后续动作。
- 异步禁言检查之后重新检查会话所有权与并发；直接召唤优先于同群的主动开话题。
- 不允许安全重试的失败会话不显示“重试”按钮。

验收通过：原生搜索在途中止、发送预检中止、已提交发送保留回执、无信号适配器的迟到结果、总时限覆盖降级与退避、三种主动/直接召唤竞争顺序。
