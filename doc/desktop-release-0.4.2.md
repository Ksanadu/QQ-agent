## 升级修复与实测

实际使用已交付的 0.4.1 安装包建立隔离基线，再运行本次正式标识的 0.4.2 安装包。初测发现旧安装器只备份 data 和旧版 SnowLuma 配置，后装技能、插件及扩展内部数据会在卸载旧程序时丢失。

修复后，卸载旧版前备份 skills/plugins；安装后完整恢复新版中不存在的自装模块，对新版已提供的模块只恢复 data/storage，避免旧代码覆盖新代码。手动迁移目录同样支持源码布局和已安装布局的扩展。

修复后的 0.4.1 → 0.4.2 实际覆盖升级通过全部 11 项校验：配置、记忆、聊天记录、表情索引、SnowLuma 登录样本、后装技能/插件的清单和入口、内置技能的 data 文件均原样保留；内置技能入口与新版打包文件哈希一致，没有被旧入口覆盖。

可复用夹具：先在明确隔离的 `desktop-qa` 安装目录运行 `node test/desktop-upgrade-fixtures.mjs prepare <安装目录>`，执行候选安装包后运行 `verify <安装目录>`。夹具只写模拟数据，拒绝 `desktop-qa` 外的路径。实际安装测试不使用日常 QQ 数据。

## 安装后运行

- 安装后显示版本 0.4.2；桌面桥接、七个设置菜单、活跃设置首项展开、关键词与人设、合并模块页均正确。
- 升级保留的技能和插件可被加载，原关闭状态保留；会话存档可读取原消息。
- 设置内 SnowLuma 一键安装入口及桌面启动/托盘选项存在。
- 再次启动只保留一个窗口；关闭窗口进入托盘，核心 HTTP 服务保持运行；可恢复窗口；正常退出后核心 HTTP 服务关闭。
- 未在验收时登录真实 QQ 或发送消息；Python/CLI、TTS 权重、ComfyUI 等外部依赖不随包分发，需按使用环境配置。
