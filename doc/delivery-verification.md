# 发送报错后的送达校验

OneBot 返回失败、连接中断或响应超时，并不一定代表消息未送达。
发送消息的公共 OneBot 调用层会在向上返回错误前核实实际消息。

- 发送前读取目标会话最近 30 条历史，记录已有消息 ID，避免把旧的相同消息误认为本次成功。
- 失败后，在有界窗口内检查自身消息回传及目标会话历史，最多查询三次。
- 必须匹配机器人账号、群/私聊对象、发送时间、全量消息段和新消息 ID。
- 文本完整匹配，包含引用和 @；图片、表情、语音、视频等使用内容 MD5 或明确的同一资源标识；JSON 卡片按完整 JSON 内容匹配。
- 本地图片和已下载网图使用已有文件/字节校验，不额外下载媒体猜测身份，也不把校验字节放入发送请求。
- 已核实送达时返回真实消息 ID 并记录一次成功，停止本次失败引起的回退重发。文字的真实送达可以满足 `send_message` 完结必要条件，但不会自动结束整个模型运行。
- 真实未送达、历史不可用且没有有效自身回传、或媒体无法证明为同一资源时，保留原失败，不伪造成功。
- 拍一拍只能通过发送后的自身通知确认，不凭普通聊天历史推断。

正常发送会增加一次本机历史查询；查询超时上限为 1.5 秒。失败校验额外等待有界，通常约 1–2 秒，最坏约 6 秒。
仅能证明消息出现在协议端历史或自身回传中，无法证明每一位群成员客户端都已显示。

验收：`npm run test:delivery`、`npm run test:images`。
