# 唤醒窗口

普通唤醒使用聊天设置的 `wakeDelayMs`。首条触发消息的发送者是本次唤醒者；等待期间该发送者的新消息会从到达时刻重新计算完整窗口，其他人的消息只参与聚批，不改变截止时间。刷新复用原等待会话，不创建第二个会话。纯 @ 触发的窗口仍至少为 5 秒，续发沿用这个窗口时长。会话开始后不再刷新等待窗口，运行期间的纯 @ 催促合并规则保持不变。

独立关联监听在“设置 → 聊天设置 → 独立关联监听”提供：

| 设置 | 配置字段 | 默认 | 范围 |
| --- | --- | --- | --- |
| 监听持续时间 | `conversationListener.idleMs` | 60 秒 | 1～3600 秒 |
| 判定前聚批 | `conversationListener.batchDelayMs` | 400 毫秒 | 0～60000 毫秒 |
| 判定后延迟唤醒 | `conversationListener.wakeDelayMs` | 200 毫秒 | 0～60000 毫秒 |

判定前聚批是固定窗口，新消息不会重新计时。LLM 判断期间的消息进入下一批；每批最多 30 条。判定相关后，所选消息的发送者集合成为该等待窗口的唤醒者，集合内任一人的新消息会刷新判定后窗口，其他人不会。后续判定不会替换已存在窗口的发送者集合。主会话忙碌时先保留相关消息，结束后按判定后延迟排队，仍可由对应发送者刷新。

修改监听持续时间和判定前聚批，对新监听生效；修改判定后延迟，对新等待窗口生效。已开始的等待窗口保持其原定时长，每次刷新均使用该时长。0 毫秒表示不额外等待。单独中止等待会话或全局中止会清理定时器与发送者集合。

验收命令：`npm run test:wake-windows`；监听运行中交接与取消回归：`node test/conversation-listener-race.mjs`。
