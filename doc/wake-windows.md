# 回复等待窗口

机器人收到召唤后立即开始思考，纯 @ 也一样。**设置 → 聊天设置 → 回复等待窗口**（原 `wakeDelayMs`）决定何时最早能发出回复，已有设置不需要迁移。截止时间从唤醒者最后一条消息实际抵达的时刻算起；0 毫秒表示不额外等待。

唤醒者续发的文字、图片、语音和引用留在同一个主会话，按接收顺序补进下一次模型请求。其他群友的消息不会延长本轮窗口：普通闲聊归入历史，直接召唤和监听确认的消息仍按自己的触发路径处理。主会话运行中，唤醒者再次纯 @ 只延长发送窗口，不另开会话。

查询类工具可以先执行。发送文字、图片、贴表情及其他有副作用的动作等到窗口结束，且模型已经读到最新补充时才执行。补充到达会淘汰尚未发出的旧稿；已经开始的外部操作仍按实际结果记账。中止会取消在途模型请求及发送等待。只有最新一版请求取得 `send_message` 成功回执才能正常完结；一轮中至少有一次工具调用成功才扣一轮，全部失败不扣；连续三轮无进展会停止继续调用普通工具。额度耗尽或连续无进展且尚未发出文字时，仍留一次仅发文字的机会。工具轮数不因补充而重置，未处理的消息仍在该会话记录里。

## 独立关联监听

| 设置 | 配置字段 | 默认 |
| --- | --- | --- |
| 监听持续时间 | `conversationListener.idleMs` | 60 秒 |
| 判定前聚批 | `conversationListener.batchDelayMs` | 400 毫秒 |
| 判定后回复等待 | `conversationListener.wakeDelayMs` | 200 毫秒 |

主会话结束后才启动监听。主会话运行期间的其他候选消息先留存，结束后结合实际回复判断；中止主会话不会启动监听。判定前聚批仍是固定窗口，新消息不会重新计时。判定相关后，如果当前群没有主会话占用，立即开始思考；否则等当前主会话结束再交接。关联唤醒只使用自己的发送等待时长，不叠加普通回复等待窗口。监听选中的发送者续发时才会刷新该窗口。

## 验收

`npm run test:wake-windows` 覆盖提前思考、窗口内补充、纯 @ 和监听交接；`npm run test:reply-trigger` 检查直接召唤；`npm run test:reply-completion` 和 `npm run test:delivery` 检查真实发送回执、完结和失败重试。
