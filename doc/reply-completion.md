# 主会话完成条件（2026-11-11）

按管理员要求，进入主 Agent 循环的会话，只有内置 `send_message` 在本次运行中向当前聊天实际发送成功后，才能正常完成。无需再由模型判断请求是不是查询任务；普通闲聊也不再允许只贴表情就标记完成。

完成凭据由 `send_message` 执行器在收到有效的 QQ 消息 ID（含负数 ID）后授予，绑定本次运行当前已处理的消息版本。收到新正文后，先前的送达仍照实记录，但不能替新内容完成。`session.sent` 非空、模型声称完成、普通文本输出、表情、图片、语音、拍一拍、跨会话发送都不能替代。重复消息被去重跳过、空消息或发送失败不授予凭据。

`finish` 未满足条件时返回工具错误，编排器不会因这个调用终止。没有后续动作时，模型可在同一批先调用 `send_message`、再调用 `finish`，无需专门请求一次模型来结束。成功发送文字不会自动收尾；还要发表情、查资料或执行其他已授权动作时，模型可继续调用工具。原先的回复安全网仍可把合适的正文转成真正的 `send_message`。

## 不完整的文字发送

一批文字部分成功时，工具返回成功消息 ID 和失败分段索引，并阻止 `finish`。调用 `send_message({"retryFailed":true})` 只补发失败部分；不必再传正文，已送达的分段不会重发。全部补齐前，另一条无关文字也不能解除这批发送的待办。用户补充使旧稿失效后，失败分段不再自动补发，应重新决定新答复。

回执缺少消息 ID、状态与返回码矛盾或连接中断时，先用真实自发回显/历史记录核验。能确认送达就沿用那条消息的 ID；异常回执仍无法确认时，将本次会话记为错误，停止后续发送，禁用整轮自动/手动重跑。应先检查 QQ 聊天记录再发新请求。

## 语音也需要当前聊天的文字确认

语音送达后，用 `send_message` 发一句简短确认，不复述语音内容，然后正常完结。合成失败、冷却或演练未发送时，改用文字答复并如实说明。跨会话语音只在当前聊天反馈结果，不擅自改成向目标发文字；当前聊天文字不会再被语音技能锁死。

## 轮次与耗时

会话详情分别显示首条当前聊天文字的送达耗时、启动前等待、模型请求、工具和 OneBot 发送回执。模型耗时包含该次请求的重试；工具耗时包含发送准备和回执，不能把回执再加一遍。JSON 模式另列发送前核验耗时及每次模型/工具的耗时，单位为毫秒。

一轮至少有一次工具调用成功才计入正常额度，整轮失败不扣。连续三轮无进展会停止普通工具调用。未成功发送文字时，模型直接停答、正常额度耗尽或达到无进展上限，都会进入一次只允许 `send_message` 的最后交付机会。宿主执行器同样限制这轮不能执行其他工具。仍未发送成功则记录“任务未完成”错误，不能标记 done，且不无限重试或编造答案。中止/取消仍可按 aborted 退出；未触发的群聊消息、独立监听分类和后台命令任务不进入这个完成判定。

验收：`npm run test:reply-completion` 检查原有文字交付和后续工具行为；`npm run test:reply-lifecycle` 检查失败分段补发、异常回执停止重试、语音后的文字确认及安全重试按钮。均使用隔离数据与模拟 QQ 接口。
