# 主会话完成条件（2026-10-30）

按管理员要求，进入主 Agent 循环的会话，只有内置 `send_message` 在本次运行中向当前聊天实际发送成功后，才能正常完成。无需再由模型判断请求是不是查询任务；普通闲聊也不再允许只贴表情就标记完成。

完成凭据由 `send_message` 执行器在收到发送队列的真实成功回执后授予，绑定本次运行上下文。`session.sent` 非空、模型声称完成、普通文本输出、表情、图片、语音、拍一拍、跨会话发送都不能替代。重复消息被去重跳过、空消息或发送失败不授予凭据。

`finish` 未满足条件时返回工具错误，编排器不会因这个调用终止。两处自动收尾（本地回复策略、核心交付收尾）也必须先取得完成凭据。原先的回复安全网仍可把合适的正文转成真正的 `send_message`；不直接把思考、工具结果或搜索摘要搬进 QQ。

模型直接停答时进入最后交付机会；正常轮次耗尽而没有文字交付时，也额外提供一次只允许 `send_message` 的模型调用。宿主执行器同样限制这轮不能执行其他工具。仍未发送成功则记录“任务未完成”错误，不能标记 done，且不无限重试或编造答案。中止/取消仍可按 aborted 退出；未触发的群聊消息、独立监听分类和后台命令任务不进入这个完成判定。

这项限制验证的是文字交付，不是答案正确性或任务步骤全部完成。事实核查、证据覆盖与多步任务验收是另外的机制。

验收：`npm run test:reply-completion`。隔离数据与模拟 QQ 接口覆盖查询后只贴表情、提前 finish、普通输出、最后交付轮、发送失败、去重、跨会话、成功完成和禁用发送权限。不会向真实 QQ 群发送验收消息。
