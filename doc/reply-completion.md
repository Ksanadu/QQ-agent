# 主会话完成条件（2026-11-01）

按管理员要求，进入主 Agent 循环的会话，只有内置 `send_message` 在本次运行中向当前聊天实际发送成功后，才能正常完成。无需再由模型判断请求是不是查询任务；普通闲聊也不再允许只贴表情就标记完成。

完成凭据由 `send_message` 执行器在收到发送队列的真实成功回执后授予，绑定本次运行当前已处理的消息版本。收到新正文后，先前的送达仍照实记录，但不能替新内容完成。`session.sent` 非空、模型声称完成、普通文本输出、表情、图片、语音、拍一拍、跨会话发送都不能替代。重复消息被去重跳过、空消息或发送失败不授予凭据。

`finish` 未满足条件时返回工具错误，编排器不会因这个调用终止。成功发送文字是正常结束的必要条件，不会触发自动收尾；工具结果仍交回模型，允许在后续轮次调用 `send_sticker`、查询资料或执行其他已授权工具，直到模型主动 `finish`、自然停止调用工具或达到正常轮次上限。旧的核心交付收尾和 `reply.local-policy` 提前结束路径已移除，插件不能因一次发送成功就截断后续操作。原先的回复安全网仍可把合适的正文转成真正的 `send_message`；不直接把思考、工具结果或搜索摘要搬进 QQ。

一轮至少有一次工具调用成功才计入正常额度，整轮失败不扣。连续三轮无进展会停止普通工具调用。未成功发送文字时，模型直接停答、正常额度耗尽或达到无进展上限，都会进入一次只允许 `send_message` 的最后交付机会。宿主执行器同样限制这轮不能执行其他工具。仍未发送成功则记录“任务未完成”错误，不能标记 done，且不无限重试或编造答案。中止/取消仍可按 aborted 退出；未触发的群聊消息、独立监听分类和后台命令任务不进入这个完成判定。

这项限制验证的是文字交付，不是答案正确性或任务步骤全部完成。事实核查、证据覆盖与多步任务验收是另外的机制。

验收：`npm run test:reply-completion`。隔离数据与模拟 QQ 接口覆盖查询后只贴表情、提前 finish、普通输出、最后交付轮、发送失败、去重、跨会话、成功完成和禁用发送权限；另验证“查表情 → 文字回复 → 下一轮发表情 → 主动结束”、文字成功后表情失败可修正、自然停答、继续操作的轮次上限，以及旧插件策略不能截断操作。不会向真实 QQ 群发送验收消息。
