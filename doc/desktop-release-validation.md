## 实际验收结果

- 运行时：Electron 33.4.11，Windows x64，应用版本 0.4.1。
- SnowLuma 官方 GitHub 最新稳定版实际下载：v2.4.0，43,339,979 字节，SHA256 与 GitHub 资产 digest 一致；最终安装版的设置按钮完整执行安装流程并切换到 data/dependencies 下的新版本目录。
- 安装器测试：重复请求共享一次安装，摘要/来源/元数据异常拒绝，原目录和登录数据保留，配置切换失败回滚。
- NSIS 0.4.0 QA 基线安装成功；以相同 QA 应用标识升级至 0.4.1，配置、记忆、聊天记录、SnowLuma 登录样本四个文件的 SHA256 全部保持一致。基线是当前代码降版本构建的升级夹具，不代表测试过所有历史安装包。
- 正式标识的最终安装包也实际安装到隔离测试目录，启动成功；已安装程序的页面渲染、一键安装按钮、重复启动单实例、原生关闭到托盘、恢复窗口、正常退出关闭核心 HTTP 服务均通过。
- 85 项页面渲染回归、11 组生图额度/管理员/交付行为回归、SnowLuma 安装保护测试通过。
- 发布审计：程序包无 SnowLuma、QQ runtime、用户 data、Cookie、个人管理员号码或临时部署脚本；保留项目许可证和运行依赖许可证。
- 修复主题脚本 CSP 摘要失配：首屏主题改为加载本机 theme-init.js，不增加 unsafe-inline。

## 使用与限制

安装包不捆绑 SnowLuma、QQ、Python/CLI、TTS 权重或 ComfyUI 工作流。依赖外部环境的技能须先配置对应服务；界面可加载不等于外部依赖已安装。QQ 登录由使用者在 SnowLuma/QQ 界面完成，本次没有操作真实账号登录，也没有向真实 QQ 发送测试消息。

生图管理员免额度改为读取本机 imageGeneration.adminUserIds 数组，公开包默认为空；现有日常实例升级时迁移原管理员配置。

桌面 UI 访问审批超时后，改用该 QA 应用自身的 Chromium/Node 调试接口验收并截图，调试端口只用于测试启动，不写入发布入口。自动审批曾拒绝移除数据隔离变量的启动测试，因此所有安装后启动均显式指定已核对的 QA 数据目录；没有以真实用户数据执行安装/升级实验。

产物未配置代码签名证书；“构建成功”不表示已取得发布者数字签名。源码与验证记录同步 GitHub，二进制单独交付。
